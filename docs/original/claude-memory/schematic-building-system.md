Buildings are authored as **declarative layered character-grid JSON** (LLM-native, per 2024-2026 literature: T2BM/BuilderGPT + VoxelCodeBench's "spatial-correctness gap" for imperative code), compiled deterministically to blocks. This replaced the procedural mound generator that produced the ugly square/entrance-less buildings the user complained about.

- **Compiler**: `src/main/java/com/formicfrontier/qa/FormicSchematic.java` — loads `formic_structures/<name>.json` from classpath; palette maps char→SEMANTIC material name (mound/dark/food_core/food_node/glow/path/moss/dirt/rooted/air — NOT raw block ids, avoids T2BM "illegal material"); origin = bottom-centre; `pos = origin + (col-halfW, y, row-halfD)` (col→X, row→Z, row0=north/-Z, max row=south/+Z); air/unmapped skipped.
- **Schematics**: `src/main/resources/formic_structures/*.json`. Author helper `scripts/gen-food-variants.py` computes smooth circular cross-sections (domes/spires/clusters) → emits the JSON (still the declarative format; just avoids hand-eyeballing circles).
- **Chosen food building**: tall termite-spire (v2). Gameplay file `food_store.json` is the campus-fit version (footprint radius ≤5 = 11 wide, height ≤14) so it clears the diplomacy caches 6 out and fits the campus mound profile.

**Gameplay integration (the eval-≠-game fix)**: real `createColony`→`ColonyBuilder`→`StructurePlacer.placeBuilding` now routes `case FOOD_STORE -> placeFoodStoreSchematic(...)` (in [StructurePlacer.java](src/main/java/com/formicfrontier/world/StructurePlacer.java)). That method: places the schematic, force-sets FOOD_CHAMBER core at centre, then re-calls the SHARED campus detailing (`placeSideChamberDetails` = cardinal offset-9 paths + culture motif + type markers; `placeSideChamberVillageYard` = courtyard + the FOOD_NODE marker at offset(-7,1,7)). `placeCampusCrownAndTunnelMouth` early-returns for FOOD_STORE (schematic provides its own closed crown). Other campus buildings (NURSERY/MINE/BARRACKS/...) still use procedural `placeCampusBuilding` — convert them the same way next.

**QUEEN_CHAMBER is also converted now** (the central "главный муравейник"): `placeQueenHall` places `formic_structures/queen_mound_a.json` (grand cathedral spire) instead of the procedural heightmap, then KEEPS all ~25 detail passes + the chamber/entrance AIR carve. Key gotcha that broke a gametest: the schematic's circular dome spilled past the queen's elliptical footprint onto the front ant-spawn approach (z=-11..-13), so the carve loop now also clears any schematic mass where `queenMoundScore(x,z) > 300` (restores the old ellipse footprint, keeps spawn headroom). The `isQueenMoundChamber` predicate caps at y<=4 so carving y=1..18 leaves the tall spire crown solid. `safeSet` overwrites NEST_MOUND/ROOTED_DIRT/etc. freely (all in `canReplace`), so detail markers win over schematic mass regardless of order. The big `starterQueenChamberUsesOrganicMoundShape` gametest is ~all detail-function asserts, not shell-block asserts, so the swap needed zero assert rewrites.

**Gotchas when converting a building**: (1) keep the building within its `siteFor` envelope or it clobbers neighbours/caches; (2) the schematic interior must NOT pre-place blocks where recurring-event markers land (famine/brood `safeSet` won't overwrite FOOD_NODE) — keep the interior hollow except the central core column; (3) the campus gametests assert the procedural mega-mound profile — rewrite those asserts to the schematic's real landmarks (hollow interior air, open entrance air, closed native cap, core block); (4) re-call the culture motif so culture-signature gametests stay green. Preview scenes `structure_preview_3q/front` now render via the REAL `placeBuilding` path so preview = game. Gate: `gradlew build` (50 gametests). See [[eval-was-a-phantom]].
